# 00009. Firmware build number

2026-06-12

## Status

Accepted

## Context

After a firmware flash, it is not obvious from the hardware alone whether the correct build was
deployed. Support conversations and bug reports are harder to act on when neither the reporter nor
the developer knows exactly which firmware version is running on the device.

A simple, monotonically incrementing build number — visible on the LCD at power-on and printed
on the serial port — provides an unambiguous reference that can be checked without a debugger or
a separate tool.

## Decision

Each CanbusMonitor build increments a build counter by one. The counter is stored in
`src/CanbusMonitor/src/build_number.h` and generated by a PlatformIO pre-build script
(`increment_build.py`). The file is not committed to version control; it is local to each
development machine and starts at 0 on a fresh clone.

The firmware version takes the form `v<MAJOR>.<MINOR>.<BUILD>`:
- `FW_MAJOR` and `FW_MINOR` are constants in `src/CanbusMonitor/src/version.h` and are
  updated by the developer for significant releases.
- `FW_BUILD` is the auto-incremented counter from `build_number.h`.

The version is displayed:
1. On LCD line 2 during power-on initialisation (`v1.0.42`).
2. On the serial port immediately after the `CANBUS_MONITOR_STARTED` line (`Firmware: v1.0.42`).

### Deployment verification

After flashing:
1. Open the serial monitor at 115200 baud (or observe the LCD at power-on).
2. Confirm the version string matches the expected build number.
3. If the version does not change after a flash, the upload likely targeted the wrong COM port
   or the bootloader did not accept the new firmware.

### Issue analysis

When a bug is reported, the reporter includes the version string shown on the LCD or serial
output. This makes it possible to:
- Pinpoint exactly which build introduced or fixed the issue.
- Confirm whether a reported fix has actually reached the device.
- Cross-reference the build number against the git log on the developer's machine
  (`git log` is the authoritative source; the build number tracks locally since `build_number.h`
  is not committed).

## Consequences

- `src/CanbusMonitor/src/build_number.h` is git-ignored; build numbers are local to each
  machine and reset to 0 on a fresh clone. Only the `FW_MAJOR`/`FW_MINOR` values are tracked
  in version control.
- The LCD startup screen shows the version briefly before the normal display takes over; no
  separate version screen is needed.
- Adding the same mechanism to other projects (CanMock, future instrument nodes) follows the
  same pattern: copy `increment_build.py`, add `extra_scripts` to `platformio.ini`, and
  include `version.h` in `main.cpp`.
